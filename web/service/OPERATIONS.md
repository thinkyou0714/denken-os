# DENKEN-OS 学習サービスの運用

既存の静的PWAを保ち、Sitesでは本人認証・D1保存・R2答案画像を使用する。Sites用の配布物にだけプラットフォーム識別メタデータを付け、GitHub Pages版は従来の端末保存を継続する。新旧の保存先を同時に正本として更新しない。

## 採用した変更と影響

| 判断 | 問題・根拠 | 変更・影響 | 戻し方 |
| --- | --- | --- | --- |
| 採用 | 既存の生成問題12,890件は通常学習の監修条件を満たしていない | 既存の確認済み52件を通常教材として配布。未監修問題は科目別の検証画面へ分離 | 教材版を戻す場合も公開ゲートを維持。未監修問題を通常学習へ一括復帰させない |
| 採用 | 一問一答では一次試験の大問・選択条件を再現できない | 2026年度一次4科目155空欄、共通解答群、選択大問、90点の分母を構造化 | 年度データは別版を登録。進行中・提出済みの模試は元の版を参照 |
| 採用 | 答案と教材の来歴、複数端末の競合が不明確 | 問題版固定、イベントID重複防止、楽観ロック、端末の保存待ち | データを書き出した上で以前のSite版へ戻す。DBは追加型の互換スキーマを保持 |

## 100案の管理

`implementation-plan.json` に100案すべての元の理由、受け入れ条件、依存関係、実装箇所、残る確認を保持した。画面の「監修・運営」から同じ内容を開ける。状態は機能の実装と運用準備を区別しており、100案すべての監修・実測が完了したという意味ではない。

## 学習UIの改修（2026年9月14日）

市場8サービスと学習科学・W3Cの資料に基づき、28項目の操作・可読性改善を実装した。比較根拠、採否、優先度、実装対応、検証範囲は [UI_RESEARCH.md](UI_RESEARCH.md) に記載し、配信先では `/service/ui-research.html` から読める。

今日の学習から一問ずつ開始し、回答後に解説と次問を表示する。学習設定と詳細な記録を別画面へ移し、公式模試は大問単位の表示と提出前確認を使う。通常演習の入力途中は利用者・問題版・モード別のタブ内下書きとして復元し、解説を見た状態も保持する。タブを閉じた後や別端末への下書き同期は対象外。

採点と保存の既存仕様を維持し、模試記録に見直しマークを追加する。テーブル構造の変更はない。2,241テストの一括確認を通過した。実ブラウザ・実機での使い心地と学習効果の実測は未実施。UIの問題時は改修前の保存済みSiteを再公開でき、答案の削除やDBの逆マイグレーションは不要である。

## 公開ゲートと巻き戻し

1. `npm run verify` と `npm run test:coverage`：lint、3種類の型検証、既存52件の内容検証、サービス教材の生成、全テスト、PWAビルド、既存の網羅率基準（文84%、分岐76%、関数91%、行89%）。
2. `npm run build`：SitesのWorker、静的ファイル、Hosting設定、Drizzleマイグレーションを生成。
3. 検証したソースをGitに保存し、その完全なコミットSHAと配布物をSitesへ保存する。
4. 所有者限定の公開を維持する。サイトを一般公開する操作はこの変更に含めない。
5. 問題時はSitesの以前の保存済み版を再公開する。ただし、ID転送の欠けるセッションは旧版で再びサインインに失敗する可能性がある。今回の修正と検証記録は [STATUS.md](STATUS.md) を参照する。
6. DBの削除・逆マイグレーションを画面の巻き戻しに連動させない。公開後のmigrationファイルは書き換えず、追加migrationで直す。

## 教材と監修

- 問題の更新は内容ハッシュによる別版。承認には監修者権限、本人確認、代表例・境界条件・反例の確認結果が必要。
- ソルバー・解の品質・物理条件の機械検証に失敗した版は、承認操作でも公開できない。
- テンプレート監修は既存の`supervision:templates:*`を継続使用する。配信時の監修レポートも書き出す。台帳をAIで承認済みにしない。
- 一次の4科目は公式の問題・解答PDFを保存し、出典と構造化した範囲を明記。公式部分点のない二次答案を自動で合否判定しない。
- 公式年度の追加画面では小問、解答、配点、選択条件を原典と人が照合する。原典PDFの文字順を自動転記結果だけで確定しない。
- 本サービスに未収録の年度・三種対策がある。収録数と習得状況を混同しない。

## 本人のデータ

- サーバーはSitesが転送した利用者IDを優先する。本文・URLのowner、メールアドレス、表示名を本人識別に使わない。私有Siteの最初の利用者が所有者になる。
- 公開ログで、Sitesの認証済みメールは届くが利用者IDが届かず `/api/me` が401となるセッションを確認した。この既存の私有Siteに限り、Sitesの所有者とDBの既存所有者を別々に確認し、`DENKEN_OWNER_FALLBACK_ID` と `DENKEN_OWNER_FALLBACK_EMAIL_SHA256` を運用環境で固定する。IDが欠ける場合だけ、転送メールの正規化後のハッシュが一致し、固定IDがDB上の有効な所有者であるときに既存IDを返す。一般のメールからのアカウント作成・所有者推測には使用しない。
- 互換設定のハッシュは `SHA256(JSON.stringify(email.trim().toLowerCase()))`。実値はGitや配布物へ記録しない。これはSitesが本人確認したヘッダーを転送する前提の処理であり、任意ヘッダーを受け付ける公開Workerへ直接移植しない。ID転送の復旧を確認後は2つの互換設定を削除して再公開できる。所有者変更・共有範囲変更時はこの固定対応を再確認する。
- ブラウザはタブで確認した所有者をリクエストへ添え、サーバー側の本人IDと違う場合は読み書きとも409で停止する。これは本人認証の代わりにはならない。初期読込が失敗した場合も前の利用者の記録を次の利用者の保存待ちへ移さない。
- 学習イベントは重複排除し、採点をサーバーで再計算する。教材版と回答が違う同一IDの再送は拒否する。
- 古いPWAのバックアップは秘密情報・ライセンスを除外し、移行直前の記録を残して取り込む。
- 別環境への復元ではノート等を同じIDで取り込み、競合を報告。移行した答案は過去の履歴として保管し、新環境の独立した学習成績から除外する。権限・監修履歴・進行中模試・画像本体は自動移行しない。
- オフライン時は前回利用者の端末内コピーを使用する。サーバーから401/403/409を受け取った場合はオフライン表示で本人確認の失敗を隠さない。再接続時に利用者が一致することを確認して再送。他端末との競合は上書きせず書き出し可能にする。
- 未送信の通常演習答案は件数・失敗理由を学習画面に表示し、「保存待ちの内容を書き出す」に含める。壊れた答案キューは空の配列に置換せず原文を保持する。模試の未同期下書きは模試画面で別途書き出す。
- API、認証経路、本人の画像はService Workerでキャッシュしない。端末内の私有コピーは利用者ごとに分離し、記録削除時に消す。
- 答案画像は30日後に参照不可。アクセス時と運営の期限切れ削除操作で物理削除する。定期削除の外部スケジュールは未設定なので、運営時には定期実行の接続または定例手動操作を設定する。
- 削除は本人の学習記録・画像・使用量を対象とし、教材の監修来歴と所有者権限を保持する。所有者削除で次の訪問者が所有者になる穴を防ぐ。

## AI・画像認識・自動収集

秘密情報はGitやブラウザへ配らず、Sitesの環境変数で設定する。現時点では外部AIを設定していない。

| 設定 | 用途 |
| --- | --- |
| `ANTHROPIC_API_KEY`、`TUTOR_MODEL` | 説明候補と本人確認前の画像転記 |
| `TUTOR_PROVIDER=compatible`、`TUTOR_MODEL`、`LLM_API_KEY`、`LLM_API_URL` | 互換APIによる説明候補。HTTPSの運営指定先のみ |
| `TUTOR_DAILY_LIMIT` | 1人1日あたりの説明候補の要求上限。既定20、最大100 |
| `REQUIRE_TUTOR_ENTITLEMENT=true` | 運営が登録した有効な会員権限をAI機能で確認。既定は無効 |
| `AUTOMATION_KEY` | 公式資料の下書き専用APIの認証。一般の会員権限を付与しない |

外部AIの自由文は説明候補として扱う。既知の根拠ID・数値式の再計算は検証するが、それで文章の意味的な正しさを保証しない。条件不足や確認できない出力は保留し、確認済み解説を残す。利用回数と同時実行の制限をサーバーで処理する。

選択したプロバイダーのモデル・キー・必要な接続先がそろった場合だけ設定済みと判定する。設定不足では外部通信や利用回数の消費をせず、確認済み解説を利用する。管理画面の「接続状況と残る準備」にDBの読込結果と各機能の設定状態を表示する。「設定済み」は外部サービスの実通信成功を意味しない。

`web/service/official-watch.n8n.json`は未稼働のワークフロー。n8nの資格情報へ認証を設定し、所有者限定Siteへの許可された外部接続経路を確認してから稼働する。認証を省くためにサイトの公開範囲を変更しない。収集は下書きで止まり、法的意味や正答、公開承認を決定しない。

参照：[n8n HTTP Request](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest)、[n8n Schedule Trigger](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.scheduletrigger)、[公式問題と利用条件](https://www.shiken.or.jp/chief/second/qa/)。
